# Пульс в Telegram: инструкция по переносу сервиса

Документ предназначен для разработчика, который допиливает текущий сервис и после этого переносит его в Telegram.

## 1. Что именно строим

Не переносим весь интерфейс в обычную переписку с ботом. Для учебного сервиса с карточками, тестами, билетами и задачами правильная схема такая:

```text
Пользователь
    |
    v
Telegram-бот
/start, кнопки, уведомления, поддержка, платежи
    |
    v
Telegram Mini App
React-интерфейс внутри Telegram
    |
    v
Node.js + Payload CMS
авторизация, материалы, прогресс, доступ, подписки
    |
    v
PostgreSQL
постоянное хранилище данных
```

Telegram Mini App — это веб-интерфейс, который открывается внутри Telegram и может полностью заменить отдельный сайт. Поэтому пользователь будет работать в Telegram, а разработчик сохранит привычный стек TypeScript/React/Node.js/Payload.

Обычный чат-бот оставляем для коротких действий:

- `/start` — приветствие и открытие приложения;
- `/help` — помощь;
- `/profile` — краткий статус пользователя;
- `/progress` — краткий прогресс;
- `/support` и `/paysupport` — поддержка;
- уведомления о новых материалах, повторении и окончании подписки.

Карточки, тесты, билеты, клинические задачи, фильтры и статистика должны открываться в Mini App, а не превращаться в длинную цепочку сообщений.

## 2. Что уже есть в текущей платформе

В локальной папке `platform/` уже подготовлен первый серверный срез:

- TypeScript + Next.js + Payload CMS;
- SQLite для локальной разработки;
- коллекция пользователей с Payload Auth;
- коллекция `learning-items` для учебных материалов;
- серверные уровни видимости `public`, `registered`, `subscription`;
- роли `student` и `admin`;
- поля плана и даты окончания подписки;
- unit- и end-to-end-тесты;
- админ-панель Payload.

В production SQLite нужно заменить на PostgreSQL. Это не означает переписывать модели: сначала переносим структуру и данные, затем подключаем Telegram-идентификатор пользователя.

## 3. Что должен предоставить владелец проекта

Перед началом интеграции нужны:

1. Имя Telegram-бота и токен от `@BotFather`.
2. HTTPS-адрес, доступный из интернета, для Mini App и webhook.
3. Сервер или облачная платформа для Node.js и PostgreSQL.
4. Решение по тарифам: что открыто гостю, после запуска Telegram, после регистрации и по подписке.
5. Список материалов, которые считаются опубликованными.
6. Название, описание, аватар и цвета бота.
7. Контакт для поддержки пользователей и платежных обращений.

Токен бота, `PAYLOAD_SECRET`, пароль базы данных и ключи платёжной системы нельзя отправлять в чат, коммитить в Git или помещать во frontend. Их хранят только в секретах окружения на сервере.

## 4. Архитектура репозитория

Рекомендуемая структура после переноса:

```text
platform/
  src/
    app/
      (frontend)/          # веб-версия и Mini App UI
      api/
        telegram/
          auth/route.ts     # проверка initData
          webhook/route.ts  # webhook Telegram
          payments/route.ts # invoice/pre-checkout/success
    bot/
      commands.ts           # /start, /help, /progress
      keyboards.ts          # inline-кнопки и кнопка открытия Mini App
      telegramClient.ts     # вызовы Bot API
    telegram/
      validateInitData.ts   # чистая функция проверки подписи
      syncTelegramUser.ts   # создание/обновление пользователя
    access/
    collections/
      Users.ts
      Subjects.ts
      LearningItems.ts
      Progress.ts
      Attempts.ts
      Favorites.ts
      Subscriptions.ts
      Payments.ts
    jobs/
      subscriptionExpiry.ts
  tests/
    unit/
    e2e/
  docs/
```

Бот и Mini App используют один backend и одну базу. Не создаём отдельную базу для Telegram и не дублируем материалы.

## 5. Идентификация пользователя

### Основной способ

При открытии Mini App Telegram передаёт frontend строку `Telegram.WebApp.initData`. Frontend отправляет эту строку на сервер. Сервер:

1. проверяет HMAC-подпись по токену бота;
2. проверяет `auth_date`, чтобы не принимать устаревшие данные;
3. извлекает Telegram `user.id` только после успешной проверки;
4. ищет пользователя по `telegramUserId`;
5. создаёт его при первом входе или обновляет имя/username;
6. выдаёт обычную серверную сессию через HttpOnly-cookie.

`initDataUnsafe` нельзя использовать для принятия решений о пользователе или доступе. Значения на клиенте никогда не являются доказательством оплаты.

### Изменение коллекции Users

В `Users.ts` добавить поля:

```ts
{
  name: 'telegramUserId',
  type: 'number',
  unique: true,
  index: true,
  admin: { readOnly: true },
},
{
  name: 'telegramUsername',
  type: 'text',
  admin: { readOnly: true },
},
{
  name: 'telegramFirstName',
  type: 'text',
  admin: { readOnly: true },
},
```

Email и пароль можно оставить для админки и веб-версии. Для пользователя Telegram отдельная форма регистрации не нужна: подтверждённый Telegram ID становится идентификатором аккаунта.

## 6. Авторизация: ожидаемый поток

```text
/start
  -> бот показывает кнопку «Открыть Пульс»
  -> Telegram открывает Mini App
  -> Mini App отправляет initData на /api/telegram/auth
  -> сервер проверяет подпись
  -> сервер находит/создаёт Users
  -> сервер ставит HttpOnly-сессию
  -> Mini App показывает доступные предметы и прогресс
```

Нельзя принимать `telegramUserId` из обычного JSON запроса без проверки `initData`. Нельзя передавать в клиент роль, план или статус оплаты как доверенный источник. Эти поля каждый раз определяются сервером.

## 7. Модель данных

Текущую коллекцию `learning-items` нужно сохранить, но для полноценного сервиса добавить отдельные сущности.

### Subjects

- `title`, `slug`;
- `description`;
- `published`;
- `sortOrder`.

Примеры: «Госпитальная хирургия», «Основы здравоохранения».

### LearningItems

Оставляем текущие поля и расширяем:

- `subject` — relationship на `Subjects`;
- `format` — card, test, ticket, case, image-case;
- `visibility` — public, registered, subscription;
- `question`, `answer`, `explanation`;
- `options` и `correctOptions` для тестов;
- `media` для задач с изображениями;
- `sourceRefs` — ссылки на источник и страницу;
- `published`.

### Progress

Одна запись на пользователя и материал:

- `user`;
- `learningItem`;
- `status` — new, learning, mastered;
- `lastSeenAt`;
- `nextReviewAt`;
- `correctCount`, `wrongCount`;
- `lastAnswerCorrect`.

### Attempts

История попыток теста или задачи:

- `user`;
- `learningItem`;
- выбранные варианты без передачи правильного ответа клиенту;
- `isCorrect`;
- `createdAt`.

### Favorites

- `user`;
- `learningItem`;
- уникальный индекс пары `user + learningItem`.

### Subscriptions и Payments

`Payments` хранит подтверждённые операции Telegram Stars, а `Subscriptions` — рассчитанное право доступа:

- `user`;
- `provider` — telegram-stars;
- `telegramPaymentChargeId`;
- `invoicePayload`;
- `status` — pending, paid, refunded, failed;
- `plan`;
- `startsAt`, `expiresAt`;
- `rawUpdateId` для идемпотентности.

Доступ проверяется через `expiresAt > now`, а не через флаг, который можно изменить из Mini App.

## 8. Как перенести материалы и базу

### Если приложение ещё только локальное

1. Зафиксировать текущую версию Git-коммитом.
2. Сохранить копию SQLite-файла и папки uploads.
3. Выполнить экспорт материалов из Payload в JSON/CSV.
4. Сопоставить старые форматы с `LearningItems`.
5. Подготовить импорт, который можно запускать повторно без дубликатов по `slug`.
6. Создать миграции Payload для новых коллекций.
7. Импортировать сначала предметы, затем материалы, затем медиа.
8. Проверить количество записей и несколько материалов каждого формата.

### Если друг передаст отдельное приложение

От него нужно получить:

- репозиторий и commit/tag готовой версии;
- список переменных окружения без самих секретов;
- схему базы данных или dump без production-секретов;
- каталог загруженных изображений;
- список API-эндпоинтов;
- формат идентификаторов материалов;
- инструкцию запуска;
- список незакрытых багов и ограничений.

Нельзя переносить production dump в открытый репозиторий. Перед переносом удалить токены, email пользователей, платёжные идентификаторы и личные данные, если они не нужны для миграции.

## 10. Оплата и разграничение доступа

Для цифровых материалов внутри Telegram использовать Telegram Stars, валюта `XTR`. Нельзя в Mini App продавать доступ к цифровым материалам через внешний эквайринг или произвольную валюту: Telegram требует Stars для цифровых товаров и услуг внутри Telegram-клиентов.

Поток оплаты:

```text
Пользователь нажимает «Оформить подписку»
  -> сервер создаёт invoice payload
  -> бот отправляет invoice в Stars
  -> Telegram присылает pre_checkout_query
  -> backend быстро подтверждает его
  -> Telegram присылает successful_payment
  -> сервер проверяет payload и charge id
  -> сервер идемпотентно создаёт Payment
  -> сервер продлевает Subscription
  -> Mini App обновляет доступ
```

Правила:

- не открывать платный материал по факту нажатия кнопки оплаты;
- открывать материал только после `successful_payment` на сервере;
- повторный webhook не должен продлить подписку второй раз;
- хранить Telegram charge ID и payload;
- реализовать `/paysupport`;
- предусмотреть возврат платежа и отзыв доступа при refund;
- писать unit-тесты на повторный webhook и истёкшую подписку.

## 11. Что остаётся веб-версией

Отдельный сайт не нужно удалять. Он полезен как:

- SEO-страница и описание курса;
- вход для администратора;
- редактор Payload;
- резервный способ доступа;
- страница поддержки и правил.

Пользовательский основной сценарий можно полностью вести через Telegram. Сайт и Mini App должны обращаться к одному backend и показывать одинаковые правила доступа.

## 12. Пошаговая реализация

### Этап A — вертикальный срез

- подключить PostgreSQL в development/staging;
- добавить `telegramUserId`;
- реализовать и протестировать `validateInitData`;
- сделать `/api/telegram/auth`;
- сделать `/start` и кнопку открытия Mini App;
- показать один предмет и одну карточку;
- сохранить один результат в `Progress`.

### Этап B — учебный контур

- вынести предметы в `Subjects`;
- перенести карточки, тесты, билеты и задачи;
- добавить прогресс, ошибки, слабые места и избранное;
- добавить изображения через Payload Media;
- добавить deep links на предмет и формат;
- проверить работу на iOS и Android Telegram.

### Этап C — доступ и монетизация

- добавить планы и сроки подписки;
- внедрить Telegram Stars;
- добавить webhook и идемпотентность;
- добавить `/paysupport` и refund flow;
- скрывать платные ответы и данные на сервере, а не только CSS-ом;
- добавить административный журнал платежей.

### Этап D — production

- PostgreSQL backup;
- HTTPS;
- secret manager или защищённые переменные окружения;
- Telegram webhook с `secret_token`;
- логи и уведомления об ошибках;
- rate limit для auth, webhook и попыток тестов;
- staging перед production;
- smoke-тест после каждого деплоя.

## 13. TDD и критерии готовности

Перед реализацией каждой функции сначала добавить тесты.

### Unit-тесты

- валидная `initData` принимается;
- неправильный hash отклоняется;
- устаревший `auth_date` отклоняется;
- один Telegram ID соответствует одному пользователю;
- гость видит только public;
- зарегистрированный видит public + registered;
- подписчик с действующим `expiresAt` видит subscription;
- просроченный подписчик не получает subscription;
- повторный payment update не дублирует entitlement;
- неправильный invoice payload не открывает доступ.

### E2E-тесты

- `/start` показывает кнопку Mini App;
- Mini App открывает каталог;
- новый Telegram-пользователь создаётся после валидной авторизации;
- карточка сохраняет прогресс;
- тест сохраняет ошибку;
- платный материал показывает понятный экран доступа;
- после успешной оплаты материал становится доступен;
- после refund доступ снимается.

### Готово, когда

- все права проверяются на сервере;
- токен бота не попадает в bundle;
- материалы не дублируются в отдельной Telegram-базе;
- повторные webhook безопасны;
- есть резервная копия базы;
- приложение открывается из кнопки бота на iOS, Android и Desktop;
- `npm run test:int`, `npm run test:e2e`, `npm run lint`, `npm run build` проходят.

## 14. Что отправить другу одним сообщением

> Нужно превратить текущий сервис в Telegram-first продукт. Не делать чат-бот с длинными сообщениями: оставить бот для `/start`, кнопок, уведомлений, поддержки и платежей, а весь учебный UI открыть в Telegram Mini App. Сохранить TypeScript/React/Node.js/Payload и одну общую базу. Добавить `telegramUserId`, серверную проверку `Telegram.WebApp.initData`, сессию через HttpOnly-cookie, коллекции `Subjects`, `Progress`, `Attempts`, `Favorites`, `Subscriptions`, `Payments`. Платный контент проверять только на сервере. Для цифровой подписки внутри Telegram использовать Telegram Stars и обрабатывать `pre_checkout_query`, `successful_payment`, refund и `/paysupport`. Сначала реализовать вертикальный срез `/start -> Mini App -> предмет -> карточка -> прогресс`, покрыть его TDD, затем переносить весь контент и оплату. Секреты не коммитить и не отправлять в чат.
