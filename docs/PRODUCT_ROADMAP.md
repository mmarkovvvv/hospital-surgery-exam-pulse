# План продукта Beep Academy

Документ описывает следующий этап после стабилизации учебных форматов. Платёжная интеграция и полноценный коммерческий запуск пока не реализуются.

## 1. Оплата и подписка

1. Выбрать платёжный сервис с поддержкой нужной страны, валюты, чеков и возвратов после проверки юристом/бухгалтером.
2. Зафиксировать тарифы: бесплатный, зарегистрированный, подписка и, при необходимости, разовая покупка курса.
3. Хранить в Payload не сам факт нажатия в интерфейсе, а серверную сущность доступа: пользователь, тариф, статус, период действия, внешний `paymentId`.
4. Создать серверные endpoints для создания платежа, возврата пользователя после оплаты и webhook платёжного сервиса.
5. Проверять подпись webhook, делать обработку идемпотентной и менять доступ только после подтверждённого события оплаты.
6. Оставить клиенту только отображение статуса. Решение «можно ли открыть материал» принимает сервер.

## 2. Полный профиль пользователя

- `Users`: имя, аватар, часовой пояс, язык, дата регистрации, Telegram ID и дата последней активности.
- Настройки обучения: выбранные предметы, текущая цель, ежедневная цель, напоминания.
- Отдельные серверные записи прогресса: освоенные материалы, ответы тестов, ошибки, избранное и последняя позиция.
- Не хранить секреты и платёжные токены в профиле; Telegram-токен и ключи остаются только в переменных окружения.

## 3. Лимиты и разграничение доступа

У каждого материала остаётся явная видимость:

- `public` — доступен гостю;
- `registered` — доступен после входа;
- `subscription` — доступен при активном серверном entitlement.

Проверка должна использоваться одинаково в web/API/Telegram Mini App. Для бесплатного тарифа можно добавить лимиты: количество новых карточек в день, число тестов и доступные разделы. Лимит проверяется на сервере, а не через `localStorage`.

## 4. Восстановление пароля

1. Подключить email adapter Payload для production-почты.
2. Оставить стандартный flow: «Забыли пароль?» → одноразовая ссылка → новый пароль.
3. Ограничить срок действия ссылки, сделать токен одноразовым и не писать его в логи.
4. Добавить rate limit на запросы восстановления и нейтральный ответ, чтобы нельзя было определить существование email.
5. Проверить сценарии регистрации, входа, выхода, восстановления и смены пароля в E2E.

## Рекомендуемый порядок реализации

1. Профиль и серверный прогресс.
2. Единый access/entitlement service и лимиты.
3. Email adapter и восстановление пароля.
4. Платёжный checkout и webhook.
5. Коммерческие экраны, аналитика и уведомления.

## Критерии готовности

- Гость видит только public-материалы.
- Зарегистрированный пользователь получает registered-материалы и сохраняет прогресс между устройствами.
- Подписка открывает subscription-материалы только после подтверждения webhook.
- Отмена или истечение подписки закрывает доступ без удаления прогресса.
- Повторный webhook не создаёт дубликат платежа или entitlement.
- Все ограничения проверяются одинаково в браузере, API и Telegram.
